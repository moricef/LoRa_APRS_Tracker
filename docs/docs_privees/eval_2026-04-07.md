## 1. CORRECTIFS APPORTÉS CETTE SESSION

### 1.1 BLE Advertising — Visibilité du device

**Problème :** Device "LoRaTracker" n'apparaissait pas sur smartphone malgré activation manuelle dans Paramètres.

**Cause :** Paquet Advertising BLE dépassait 31 octets (limite standard BLE 4.0). NimBLE rejetait silencieusement le nom si UUID + flags + name ne rentraient pas dans un seul paquet.

**Solution :** 
- Paquet principal (Advertisement) : flags + UUID du service APRS
- Paquet secondaire (ScanResponse) : nom du device "LoRaTracker"

**Résultat :** ✅ Visibilité restaurée. Device découvrable via scan Bluetooth standard.

**Commit :** `70b74269`

---

### 1.2 Configuration JSON — Corruption mémoire

**Problème :** Crash `LoadProhibited` à `0x8200d9aa` lors de `Config: Saving config..` après corruption/format LittleFS.

**Cause :** Deux `DynamicJsonDocument(8192)` alloués simultanément (readFile + writeFile) → fragmentation PSRAM → allocation échouée dans multi_heap.

**Solution :** Scoper le premier document JSON en `readFile()` pour garantir destruction **avant** appel à `writeFile()`.

```cpp
bool needsRewrite = false;
{
    DynamicJsonDocument data(8192);
    DeserializationError error = deserializeJson(data, configFile);
    // ... désérialisation ...
}  // ← Document détruit ici

if (needsRewrite) {
    writeFile();  // ← Nouvelle allocation en mémoire propre
}
```

**Résultat :** ✅ Pas de corruption mémoire. Config se sauvegarde sans erreur.

**Commit :** `70b74269`

### 1.3 Carte SD — Erreurs de token SPI

**Problème :** Erreurs répétées `token error [17] 0x4` → `Failed to open log file` → `Failed to open stats file for writing`

**Pattern :** 
- Toutes les 5–10 secondes (timing du logging SD)
- Coïncide avec tentatives d'ouverture de fichiers
- Cause : Bus SPI partagé (SD + écran + LoRa) sans protection mutuelle

**Cause racine :** Driver SD (`sd_diskio.cpp`) appelait `sdCommand()` sans prendre le mutex `spiMutex` déjà utilisé par LoRa/écran/carte. Une interruption LoRa/écran pendant une transaction SD corrompait le flux et provoquait une erreur de token.

**Solution :** Ajouter `extern SemaphoreHandle_t spiMutex;` dans :
- `src/sd_logger.cpp` : prendre `spiMutex` (récursif, timeout 100ms) avant chaque `fopen/fclose` dans `sdLogVprintf()` et `log()`
- `src/storage_utils.cpp` : idem pour `saveStats()`, `loadStats()`, `saveContacts()`, `loadFrames()`, etc.

Avec vérification NULL pour démarrage précoce (avant init LVGL).

**Résultat :** ✅ Pas d'erreurs de token observées après correction. Logging SD stable.

**Commit :** `392ae719`

### 1.4 Traces GPS — Persistance et nettoyage

**Problème :** 
- Traces GPS perdues à chaque fermeture de carte (fichier `.bin` effacé à `init()`)
- Ancien fichier trace pas supprimé au boot → visible au redémarrage
- Génération de path ambiguë : `trace_nodate.bin` si pas de fix GPS au boot

**Cause :** 
- `TraceSD::init()` appelée à chaque ouverture carte → effacement du fichier
- Pas d'effacement au boot → ancien fichier persiste
- Effacement tentait du fichier courant uniquement, pas tous les fichiers du dossier

**Solution :**
1. Séparer deux fonctions :
   - `clearPreviousTrace()` : appelée une fois au boot (dans `setup()`) → supprime **tous** les `.bin` du dossier `/LoRa_Tracker/trace/`
   - `init()` : appelée à chaque ouverture de carte → crée dossier si nécessaire, met à jour path, **sans effacer**

2. Cleanup au boot parcourt le dossier et supprime toutes les entrées, indépendamment du nom/date.

```cpp
File dir = SD.open("/LoRa_Tracker/trace");
while ((entry = dir.openNextFile())) {
    String name = String("/LoRa_Tracker/trace/") + entry.name();
    SD.remove(name);  // Supprime tous les fichiers
}
```

**Résultat :** 
- ✅ Traces persistent pendant la session (4h de trajet = fichier `.bin` continu)
- ✅ Ancien fichier supprimé au reboot
- ✅ Bouton GPX `play/stop` existant permet export `.gpx` avant fermeture si souhaité

**Commit :** `392ae719`

- **Nominal :** ~1,2 MB libre

## 9. LIMITATIONS CONNUES

1. **Fragmentation PSRAM :** Après N cycles ouverture/fermeture carte, plus grand bloc libre peut se dégrader. Contournement : utiliser pattern persistance sprite.
2. **Timing dual-framework :** Démarrage WiFi/BLE doit être différé (activation manuelle) pour éviter contention stack avec init LVGL.
3. **Performance carte SD :** Bus SPI partagé avec écran/LoRa → contention mutex sous charge. Acceptable, mais logging peut être occasionnellement retardé.
4. **Délai fix GPS :** Première session peut utiliser `trace_nodate.bin` si GPS pas fixé à ouverture carte. Fichier auto-renommé quand fix obtenu (pas encore implémenté, TODO).
